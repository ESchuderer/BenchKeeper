# BenchKeeper

Agents (Claude Code, Codex) run on the host in the repository or worktree. File edits, Git and `gh` stay on the host, and so does the `skills` CLI install below (agent tooling). `node`, `npm` and `npx` run only in the dev container (`.devcontainer/`: Node 22.23.3, Playwright MCP 0.0.83 with Chromium, the Chromium headless shell of `@playwright/test` 1.64.1). When that version changes in `web/package.json`, change it in `.devcontainer/Dockerfile` too. Start it: `devcontainer up --docker-path podman --workspace-folder .`. Prefix: `devcontainer exec --docker-path podman --workspace-folder .`, compound commands as `... sh -lc 'cd web && npm ci && npm run build'`. `.mcp.json` and `.codex/config.toml` start Playwright MCP in the container through the same prefix (they run `devcontainer up` first, at the repository root). VS Code attached to the container: set `dev.containers.copyGitConfig` to `false` and `dev.containers.gitCredentialHelperConfigLocation` to `none` in the local user settings (the extension reads them only there), and do not forward the SSH agent.

## Checks
- Links: CI (`.github/workflows/links.yml`). Job `link-check` (pull requests and pushes) runs lychee offline over the Markdown files (relative links and anchors) plus the link checker test. External links (all hosts through lychee, github.com through `.github/scripts/github-links.mjs` and the GitHub API) are checked by the jobs `external-links` and `external-site-links` on the weekly cron and `workflow_dispatch` only, so a broken external link shows as a red scheduled run. Required check `lychee` is the gate over `link-check`. Link checker test: `devcontainer exec --docker-path podman --workspace-folder . node --test .github/scripts/github-links.test.mjs`
- Repository: CI (`.github/workflows/checks.yml`): `actionlint`, `zizmor` (a checkout keeps its credentials only with a `zizmor: ignore[artipacked]` reason), dependency review on pull requests, no em dash or emoji in text files outside the vendored `.agents/` and `.claude/` folders and the recorded trial data in `bench/results/*/round-*`, SKILL.md `description` in double quotes. Actions are pinned to commit SHAs with a version comment. Dependabot (`.github/dependabot.yml`) updates the `uses:` pins and the site's npm packages weekly. The actionlint image digest, `node-version` and the Claude Code pin of the `plugin-checks` job (`.github/claude-code/package.json` and its lockfile, the npm `stable` tag) are bumped by hand.
- CI structure (all workflows): `checks.yml` runs `checks-core`, `app-ui-tests` and `plugin-checks` in parallel and `checks` gates all three; `links.yml` gates its `link-check` job the same way. `permissions: {}` at the top and per job, `timeout-minutes` on every job, `concurrency` that cancels superseded pull request runs. Every check runs on pull requests into `main` and on pushes to `main`, except `conventional` (the pull request title) and `dependency-review`, which run on pull requests only. Keep the names of required checks (`checks`, `app (ubuntu-latest)`, `app (macos-latest)`, `app-windows-smoke`, `build`, `lychee`, `conventional`, `dependency-review`) when changing jobs: the rulesets name them.
- App coverage: `npm run test:coverage` in `app/` (CI job `app` runs it instead of `npm test`) prints the summary and fails below the floors for lines, branches and functions, set in that script in `app/package.json` a little under the measured values (98.8, 91.2, 96.1); raise them when coverage rises. It counts `src/**` and `ui/*.js`, not `ui/api.js` (browser fetch wrapper, covered by the UI tests) nor the `draw()` page script of `src/board.mjs` (browser-only, `node:coverage disable`).
- Site: CI (`.github/workflows/pages.yml`): README sync, build, axe in light and dark, lychee offline on the built HTML (relative links; its external links are the weekly `external-site-links`). Deploys to GitHub Pages from `main`: job `bundle` builds the site and uploads it, job `deploy` publishes it; a failing `build` check job fails the run and the previous deployment stays. Pushes share one concurrency group, so deployments are ordered. The `github-pages` environment allows deployments from `main`
- Site locally: `devcontainer exec --docker-path podman --workspace-folder . sh -lc 'cd web && npm ci && npm run build && npm test'`. Preview (`npm run preview`) under `/BenchKeeper/` on a free host port: `podman port $(podman ps -q --filter label=devcontainer.local_folder="$PWD") 4321`

## Conventions
- Branches: `main` is the only long-lived branch and the default. Branches are short-lived and pull requests target `main` (squash merge, linear history). Merging a pull request that raises the setup version is the release: the Release deploy and the npm publish run on pushes to `main`.
- `plugins/benchkeeper/rules/global.md` applies here: no em dash, no emojis, facts only.
- Default tier: research
- Pre-push review: `plugins/` counts as code, not docs.
- Every install command in docs pins an exact version (`pkg@x.y.z`); BenchKeeper's own marketplace follows the branch `stable`. `npx benchkeeper@<version>` and the clone tag come from `app/package.json`: the Release workflow rewrites them on the release pull request with `.github/scripts/version-pins.mjs`, and CI checks them. Do not run it or edit them for a feature change. `/benchkeeper:maintaining-repos` proposes bumps. The app installs host tools at the newest release at least 7 days old instead of a pin. The skills CLI runs at the same newest release at least 7 days old; `SKILLS_CLI` is only its minimum. Ponytail's and Matt Pocock's plugins and all skill sources are not pinned.
- SKILL.md front matter: `description` in double quotes (it contains colons). CI runs `.github/scripts/skill-lint.mjs` on own skills.
- Editing `plugins/benchkeeper/skills/` or `plugins/benchkeeper/rules/`: call the Skill tool with `mattpocock-skills:writing-for-agents`. Each skill has `agents/openai.yaml` for Codex: user-invoked skills set `allow_implicit_invocation: false`.
- `plugins/benchkeeper/library/`: the skill library that `setting-up-projects` installs per project. `library.json` is the source (skills, packs; community skills follow the default branch of their source). `README.md` tables are generated: `devcontainer exec --docker-path podman --workspace-folder . node .github/scripts/library-readme.mjs`. The plugin does not load it. Own library skills follow the `skills/` conventions (SKILL.md, `agents/openai.yaml`).
- Plugin: `.claude-plugin/marketplace.json` (both agents read it) lists `plugins/benchkeeper/`. Its `version` in `.claude-plugin/plugin.json` and `.codex-plugin/plugin.json` equals the setup version and is set by the release pull request. Check: `claude plugin validate plugins/benchkeeper --strict` and `claude plugin validate .` (CI job `plugin-checks` runs both with the plugin mod tests and the failing-fixture test `.github/scripts/plugin-validate.test.mjs`). Try a change for one session: `claude --plugin-dir plugins/benchkeeper`. After a release, ask the user to update the plugin (`claude plugin marketplace update benchkeeper && claude plugin update benchkeeper@benchkeeper`, Codex: `codex plugin marketplace upgrade benchkeeper`) and, when `rules/global.md` or the global steps changed, to run `npx benchkeeper@<version> apply`. Neither starts on its own.
- repo-baseline settings profiles: `app/src/baseline.mjs` pins the `ESchuderer/repo-baseline` commit (`REF`) that `app/src/baseline/` (profiles, caller workflows and templates) is a copy of. A new pin: change `REF`, run `devcontainer exec --docker-path podman --workspace-folder . node app/scripts/baseline-sync.mjs` (`--check` lists differences), commit both. Tests stub `gh`; never write a real repository's settings while developing: applying a profile is repo-baseline's `scripts/apply.mjs`.
- `bench/` keeps only what has not moved yet to ESchuderer/BenchKeeper-research: `bench/PROTOCOL.md` and the files `bench/ORIGIN.md` there lists under "Not moved yet" (the site no longer has `/bench/` pages; its links point to that repository). The run machinery and raw run data (transcripts, app archives, screenshots) were removed in #256 and are not available; the last release that had them is setup-v6.8. The benches before mistreevous and their briefs were removed in #266. Do not add new runs or results here: add them in BenchKeeper-research.
- Setup versions: tags `setup-v<major>.<minor>.<patch>` and `CHANGELOG.md`, made by release-please (`release-please-config.json`, `.github/workflows/release.yml`), not by hand. A pull request title is a Conventional Commit (`feat`, `fix`, `perf`, `chore`, `docs` and so on, checked by `.github/workflows/pr-title.yml`); it becomes the squash commit and the changelog line. `feat` raises the minor version, `fix` and `perf` the patch version, `!` or a `BREAKING CHANGE:` footer the major version. A change users should receive (under `plugins/benchkeeper/` or `app/`) needs one of those types: `docs`, `refactor`, `test`, `chore` and `ci` release nothing. Never change `version` in `app/package.json`, `app/package-lock.json` or the `plugin.json` files and never edit `CHANGELOG.md` for a change; notes that matter to a reader go in the pull request description, which GitHub copies into the squash commit body. Merging to `main` releases nothing: release-please keeps one release pull request open, `.github/workflows/release-weekly.yml` merges it every Monday 14:00 Europe/Berlin (the label `hold` skips a week), and merging it tags the version, moves the branch `stable` to it (the ref the app adds BenchKeeper's marketplace at), creates the GitHub Release and, if npm lacks `app/package.json`'s version, starts `npm.yml` to publish it.
- Description (README), quickstart (README, `app/README.md` and the site), levels, prerequisites and frameworks (`docs/setup.md`), core framework, recommended tools and OpenHands (`docs/stack.md`), SDLC steps (site only): edit `web/src/data/facts.json`, then run `devcontainer exec --docker-path podman --workspace-folder . node web/scripts/readme.mjs`. Never edit the generated README blocks by hand.
- App (`app/`): package `benchkeeper`, its `version` equals the plugin `version` (release-please sets both). Rules and skills come from `plugins/benchkeeper` (copied into `app/content/` at pack time). Tests: `devcontainer exec --docker-path podman --workspace-folder . sh -lc 'cd app && npm ci && npm test'`. Never run `apply` against the real home directory while developing: tests use a temporary one (`BENCHKEEPER_HOME`). The site's `/app/` page pictures the UI test server in demo mode (fixture home, never a real one): a PR that changes a pictured view regenerates `web/public/app/*.png` with `devcontainer exec --docker-path podman --workspace-folder . sh -lc 'cd app && npm run build && npm run screenshots'`.
- `.agents/skills/skill-creator` is vendored from `anthropics/skills` (`skills-lock.json`): do not edit. Update with `DO_NOT_TRACK=1 npx -y skills@1.7.2 add anthropics/skills -s skill-creator -a claude-code -a codex --copy -y`.
- Evaluations live in `evaluations/<category>/<tool>.md`, indexed in `EVALUATIONS.md`. Update both when a component is added, removed, changed, or new evidence appears.
- `web/scripts/og.svg` is the source of `web/public/og.png`: `rsvg-convert -w 1200 -h 630`.
