This repository is mistreevous, a TypeScript library to define behaviour trees in MDSL or JSON and step them for an agent. You are a maintainer, and you are picking up this feature request from a user:

> I'm exploring mistreevous for long-running workflows (implementation, review, CI, human approval). A workflow may wait hours or days for external events, and the Node.js process might restart in the meantime. Could a tree's execution state be serialized and restored? For example a `snapshot()` / `restore()` API that preserves node progress, retry and repeat counters, and wait timing. Storage, event handling and scheduling can stay in the application, so the library stays lightweight.

Add this to `BehaviourTree`:

- `snapshot()` returns the tree's execution state as a plain object that survives `JSON.stringify` and `JSON.parse` unchanged (no functions, no class instances). Export its type from the package.
- `restore(snapshot)` sets a tree built from the same definition to that state. From then on the tree behaves exactly as the tree the snapshot was taken from would have: the same node states (as `getTreeNodeDetails()` shows them), the same agent functions called in the same order, the same result.
- What a snapshot keeps: the state of every node, which children of composite nodes are done or running, the iteration and attempt counts of `repeat` and `retry` nodes, random choices already made (random iteration and attempt counts, the child a `lotto` node picked, random `wait` durations), and how long a `wait` node has waited.
- A restored `wait` node waits only for the remaining time. Time that passes between taking the snapshot and restoring it does not count. This holds for the clock (`Date`) and for the `getDeltaTime` option.
- A snapshot of a finished tree restores as finished; the next `step()` starts a new run, which makes its random choices again.
- Document the API in the README, with an example.
