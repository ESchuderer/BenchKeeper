# OpenSpec

[Repository](https://github.com/Fission-AI/OpenSpec), Category: workflow frameworks, Checked 2026-10-17, Decision: Out (setup-v3.0)

## Independent evidence

- None with a no-spec baseline.
- [harness-abc-bench](https://github.com/tonydzi/harness-abc-bench) pre-registered a Claude Code comparison (3 tasks x 3 arms, blind panel): baseline, Superpowers v6.2.0, OpenSpec v1.8.0. Spec Kit is a reserve arm. No results published as of 2026-10-14.

## Benchmark

Arm: AB (OpenSpec alone). Arm definitions: [bench/SCENARIOS.md](https://github.com/ESchuderer/BenchKeeper-research/blob/main/bench/SCENARIOS.md).

Brownfield run on Sonnet 5.5, Claude Code, k = 3 ([mistreevous](https://github.com/ESchuderer/BenchKeeper-research/blob/main/bench/results/2026-10-18-mistreevous.md)): median brownfield score 88.4 against 87.0 for plain Claude Code (A), inside the spread, at 1.1 times the cost and 1.4 times the time. The agent never ran the OpenSpec tools.

## Skill authoring check

Rank 5 of 8 (tied), review 3.1, static checks 100% (generated by 1.14.1): guarded destructive steps. The same preamble in all 6 skills. Merge rules restated next to the CLI. No evaluations. Details: [bench/results/2026-10-16-skill-authoring.md](../../bench/results/2026-10-16-skill-authoring.md).

## Decision

Out (setup-v3.0, 2026-10-17): Matt Pocock's skills keep specs and tickets in the repository's issue tracker (`docs/agents/issue-tracker.md`), so a second spec owner is not needed. Own run, signal only: on mistreevous (brownfield, k = 3) OpenSpec alone (AB) scored 88.4 against 87.0 for plain Claude Code, inside the spread, and the agent never ran the OpenSpec tools.

What it adds (one folder per change, deltas merged into `openspec/specs/` on archive, `openspec validate --strict`) still fits repositories that want per-change spec history. `setting-up-projects` keeps an existing `openspec/` when the user asks. A global OpenSpec CLI from earlier setups is removed with `npm rm -g @fission-ai/openspec` (setup-v4.0 `setup.sh` does not list it).
