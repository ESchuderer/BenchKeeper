# CedarLoom packages

The CedarLoom packages (`@cedarloom/*`), developed in this repository until CedarLoom has its own. They form a pnpm workspace on Node 26 with strict TypeScript 7; the BenchKeeper app (`app/`) and the site (`web/`) stay separate npm projects outside it. The commands below need pnpm 12.16.1 on the `PATH` (`npm install -g pnpm@12.16.1`); `package.json` names no `packageManager`, because GitHub's dependency graph does not read the lockfile that field produces.

| Command                                                    | Runs                                                                                                                                                                                         |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm install`                                             | the install                                                                                                                                                                                  |
| `pnpm run typecheck`                                       | `tsc -b` over every package and its tests                                                                                                                                                    |
| `pnpm run lint`                                            | Oxlint with type-aware rules and the import boundaries of `.oxlintrc.json`                                                                                                                   |
| `pnpm run format`                                          | Biome formatting (`format:check` only reports)                                                                                                                                               |
| `pnpm run knip`, `pnpm run jscpd`                          | unused files, exports and dependencies; duplicated code                                                                                                                                      |
| `pnpm test`                                                | Vitest with a coverage report in each package, then the root checks in `scripts/`                                                                                                            |
| `pnpm --filter @cedarloom/contracts run generate`          | rewrites the JSON Schema and OpenAPI documents after a schema change; a test fails while they differ                                                                                         |
| `pnpm --filter @cedarloom/extension-orca run build`        | builds the app's own Orca extension into `packages/cli/extensions/`, where the CLI finds it (`cedarloom orca status`, the doctor)                                                            |
| `pnpm --filter @cedarloom/extension-claude-swap run build` | builds the app's own claude-swap extension there too (`cedarloom claude-swap status`, `cedarloom claude-swap install`, which runs uv or pipx only once named with `--allow`, and the doctor) |

CI runs these in `.github/workflows/cedarloom.yml` for the changed packages and their dependents; its job `check` is the one result to require. A pull request over 30 files or 1000 changed lines in these paths (lockfile and generated documents excluded) fails until the owner sets the `size-override` label.

The CLI reaches the OS credential store (Keychain, Credential Manager, Secret Service) through `@napi-rs/keyring`. Its Linux binaries statically link libdbus, licensed `AFL-2.1 OR GPL-2.0-or-later`; CedarLoom uses it under AFL-2.1, and each Linux platform package ships that license and its notices in `LICENSE.third-party.md` ([keyring-node](https://github.com/Brooooooklyn/keyring-node#bundled-rust-dependencies)).

The extension-host tests run the sandbox conformance kit inside `@anthropic-ai/sandbox-runtime`, which needs bubblewrap, socat and ripgrep on Linux and ripgrep on macOS. Where no sandboxed process starts, as in the rootless dev container (bubblewrap cannot mount `/proc` or `/dev/pts` there), the test is skipped outside CI; on CI it must run. On Ubuntu 24.04 and later srt needs `kernel.apparmor_restrict_unprivileged_userns=0`, and from 25.04 also the `bwrap-userns-restrict` AppArmor profile unloaded, as the test job does; without them its sandbox does not start, and a community extension fails to start with bubblewrap's error.
