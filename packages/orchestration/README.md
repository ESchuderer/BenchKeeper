# @cedarloom/orchestration

Launches CedarLoom's workers: their clean environment, the paths and hosts they may not reach, the checks that refuse a launch, and the guard hook that reads every shell command a worker's Claude Code session runs.

## The guard hook

`@cedarloom/orchestration/guard-hook` is a Claude Code `PreToolUse` command hook for the Bash and Monitor tools. It takes its policy as JSON in its argument, reads the call from stdin, and refuses with exit code 2 and the reason on stderr. It stops agent mistakes, not a determined hostile agent: for a worker, the narrow token is the hard limit (A13).

It reads a command by structure and refuses every form outside this grammar (A79): simple commands with their assignments, redirections and wrappers (`env`, `command`, `builtin`, `exec`, `nohup`, `time`, `nice`, `timeout`, `stdbuf`, `setsid`, `ionice`, `caffeinate`, `xargs`, each with the options it knows); pipelines and lists; quotes, parameter expansions, `$(...)` and arithmetic that holds no command; heredocs and here-strings, an unquoted heredoc's `$(...)` read too; and `if`, `for`, `while` and `until`, every condition and body command read.

It also refuses when it cannot read the call at all: input that is no JSON, a missing or invalid policy, a call without its command or folder, a crash or a timeout (the launch sets `onFailure: "block"`).

### In a worker session

The launch gives every worker the hook through `--settings`: a `PreToolUse` hook on `Bash|Monitor|PowerShell|Agent` in exec form (this Node.js, the hook's file, the policy's JSON), `timeout` 10 and `onFailure: "block"`. The policy holds the GitHub repositories of the project's `origin` remote (pending owner decision: not a fork's upstream), the hub this machine binds, and the memory repository it binds (`cedarloom profiles bind memory <owner/repo>`), whose pushes reach its `memory/` branches only. What keeps the worker from switching the hook off:

| Way round                                                                                                                                       | What stops it                                                                                                                                                                                                                                          |
| ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `disableAllHooks` in a settings file, also one written mid-session                                                                              | the launch reads no settings file (`--setting-sources ""`), and its `--settings` say `"disableAllHooks": false`, which outranks local, project and user settings ([settings precedence](https://code.claude.com/docs/en/settings#settings-precedence)) |
| `disableAllHooks`, `allowManagedHooksOnly`, `allowManagedPermissionRulesOnly` or `strictPluginOnlyCustomization` with hooks in managed settings | the launch refuses to start (`launch.sandbox-overridden`)                                                                                                                                                                                              |
| rewriting the hook or the contracts it reads its policy with                                                                                    | both packages' folders are closed to the file tools (`Edit` deny) and to commands (`sandbox.filesystem.denyWrite`); they, node, git and the hook's other dependencies lie outside the working folders, and git comes from an absolute folder of `PATH` |
| a crash, a timeout or invalid output of the hook                                                                                                | `onFailure: "block"` refuses the call                                                                                                                                                                                                                  |
| `--bare` or `CLAUDE_CODE_SIMPLE`, which skip `--settings` hooks                                                                                 | the launch never passes `--bare`, and the worker's environment is an allowlist                                                                                                                                                                         |
| PowerShell                                                                                                                                      | `CLAUDE_CODE_USE_POWERSHELL_TOOL=0`, and the hook refuses PowerShell calls                                                                                                                                                                             |
| a tool beyond a worker's, such as `RemoteTrigger`, `SendMessage`, `WebFetch` or one a later version adds                                        | `--tools` names the built-in tools a worker gets, and MCP tools are denied (`mcp__*`)                                                                                                                                                                  |
| the `Agent` tool with `isolation: "remote"`, a subagent in the cloud                                                                            | the hook refuses it                                                                                                                                                                                                                                    |

Not covered: MDM profiles, the Windows registry and server-managed settings, which the launch does not read. No worker starts on a Claude Code older than 2.1.295, which ignores `onFailure`, nor on native Windows: Claude Code has no command sandbox there, and the launch requires one (`failIfUnavailable`).

### The OS credential store

The `hub-issues` token sits in the OS credential store, and the `cedarloom work-items` commands that use it are the owner's. Nothing in them tells who asks, so the worker's sandbox is the boundary (owner decision, 2026-11-08). A trial on macOS 27.0 with Claude Code 2.1.316 launched a worker with CedarLoom's arguments and settings, with Bash allowed for `node` and `printf`. Reading and writing a keychain entry through `@napi-rs/keyring`, and `cedarloom work-items token`, each failed with "A default keychain could not be found". They failed the same way with `~/Library/Keychains` taken off the read-deny list. The commands that need no token fail too, because a worker writes only its working folder, its result folder and its temporary folder. With a CedarLoom state and config folder under the home folder, `work-items comment --yes` could not read the hub binding, and `work-items mirror --yes` could not open the ledger ("unable to open database file"). Nothing was queued or written. Not tried: Linux, where the Secret Service is reached over the D-Bus session socket. There the worker's environment allowlist is no boundary, as a worker can set `DBUS_SESSION_BUS_ADDRESS` in its own command; the sandbox's block of Unix sockets is what has to hold.

### Everyday forms it refuses

| Form                                                                                                                                                                              | Instead                                                              |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| a subshell `(cd x && make)`, a group `{ a; b; } > f`                                                                                                                              | `cd x && make`, `git -C x`, `make -C x`; one redirection per command |
| a function, `case`, `select`, `coproc`, `for x do` without `in`                                                                                                                   | `if` and `elif`                                                      |
| `[[ $x =~ (a\|b) ]]`, any `(` right after a word                                                                                                                                  | `grep -E`                                                            |
| a process substitution, `diff <(sort a) <(sort b)`                                                                                                                                | temporary files                                                      |
| backquotes, also inside double quotes and unquoted heredocs; an unquoted heredoc line ending in `\`                                                                               | `$(...)`; a quoted heredoc (`<<'EOF'`) for text with backquotes      |
| `$(( $(cmd) + 1 ))`, `[[ $(cmd) -gt 0 ]]`                                                                                                                                         | `n=$(cmd)` first                                                     |
| `(( n > 0 ))`, bash's `$[ … ]`                                                                                                                                                    | `[ "$n" -gt 0 ]`, `$(( … ))`                                         |
| `bash -c`, `sh -c`, a shell reading a pipe, heredoc or here-string, `source /dev/stdin`, `eval`, `trap`, `alias`, `hash`, `watch`, `emulate`, `compgen`, `complete`, `mapfile -C` | the command itself, or a script file                                 |
| `find -exec`, `-execdir`, `-ok`, `-okdir`                                                                                                                                         | `find ... -print0 \| xargs -0 <program>`                             |
| `xargs` in front of gh, git, curl, a shell or a wrapper                                                                                                                           | a `for` or `while read` loop                                         |
| a wrapper option it does not know (`env -S`, `env -P`, `nice -10`, an abbreviated long option)                                                                                    | the options it lists, spelled out                                    |
| a command named by a variable or a glob (`$PYTHON x.py`)                                                                                                                          | the program's name                                                   |
| `printf -v`, `read -a` or `-ra`, `let`, `declare -i`; `export`, `read` or `env -u` of a name it cannot read (`export $(cat .env \| xargs)`)                                       | names written out; `read -r a b c`, one name per word                |
| zsh's `=cmd`, `noglob`, `nocorrect`, `-`, glob qualifiers, `=(...)`, `${(...)...}`, short `if [[ ... ]] cmd`                                                                      | the bash forms                                                       |
| the PowerShell tool                                                                                                                                                               | the Bash tool                                                        |

| Form                                                                                                                                                                                                                                                                           | Instead                                            |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------- |
| `git push --force`, `-f`, `+branch`, `--force-with-lease`, `--mirror`                                                                                                                                                                                                          | a new branch and a pull request                    |
| `--no-verify`, `git commit -n`                                                                                                                                                                                                                                                 | fix what the hooks report                          |
| `git -c key=value`, `git config key value`, `git remote add` or `set-url`, `git clone -c`                                                                                                                                                                                      | the repository's configuration as the owner set it |
| `git rebase -x`, `git submodule foreach`, `git bisect run`, `git difftool --extcmd`, `git grep -O`, `--upload-pack`                                                                                                                                                            | the command itself                                 |
| an alias or another git command the guard does not know, `git $sub`, a word it cannot read where an option may stand                                                                                                                                                           | the command's own name and literal options         |
| a remote, URL or folder it cannot tell (`--git-dir`, `env -C`), a repository outside the session's                                                                                                                                                                             | the session's repositories by their remote name    |
| a push that may update `main` of the memory repository: also `memory/<name>` without a destination, and a typed URL the checkout's `url.<base>.pushInsteadOf` sends there; not a configured `+` refspec, a rewrite the same command writes or a `pre-push` hook (Known limits) | `HEAD:memory/<name>`                               |
| `GIT_*` variables but `GIT_PAGER` and `GIT_TERMINAL_PROMPT`, `EDITOR`, `VISUAL`, `CDPATH`                                                                                                                                                                                      | options on the command line                        |

### Known limits

- Data run as code when it expands: a variable's value used in arithmetic or as a subscript (`x='y[$(cmd)]'; echo $((x))`), `${x@P}`, `PS4` with `set -x`. A subscript written out with a command in it refuses, as does arithmetic in `[[ ]]` on anything but a number or a plain `$name`, and `$'...'` with a numeric escape.
- Script files and interpreters (`bash x.sh`, `npm run x`, `make`, `python3 -c`, `node -e`), and programs that run their arguments which the guard does not list (`flock`, `parallel`, `script -c`, `ssh`).
- File writes: `.git/config` and git hooks, a shell's startup files, Claude Code's settings files.
- Git configuration and hooks: workers keep writing them, as skills and setup tools install hooks there, and the guard reads no push configuration (owner decision, 2026-11-08). A `+` refspec in `remote.<name>.push` force-pushes a push named without refspecs (`git push origin`), and `remote.<name>.mirror = true` makes a plain `git push origin` force-update `main` and push every ref. A `url.<base>.pushInsteadOf` rewrite or a `pre-push` hook (also through `core.hooksPath`) can send a push elsewhere, `main` of the memory repository included. The guard applies the rewrites the configuration holds when it reads a command to typed URLs and named remotes, but not one that the same command writes. The memory repository's `main` has no server-side rule, so nothing on GitHub refuses such a push.
- A skill's inline command (`` !`cmd` `` or a ` ```! ` block) runs without any `PreToolUse` hook, the guard's included, once the skill's own `allowed-tools` pre-approve it. The sandbox is its only limit (owner decision, 2026-11-08: no `disableSkillShellExecution`). In a trial with Claude Code 2.1.316, a plugin skill's `` !`sh -c '…'` ``, which the guard refuses as a Bash call, ran, and a write outside the working folders failed in the sandbox. The guard as a plugin's `PreToolUse` hook does fire for the Bash calls of the agents a workflow script starts.
- A word whose value the shell knows only when it runs, such as `find . "$a"` with `a=-exec`; zsh beyond the forms above, such as `print -v` and `set -A`.
