# @cedarloom/sessions

Reads every agent session of this machine from the agent tools' own session logs (Claude Code's transcripts and Codex's rollouts), on demand: its project, agent time, tokens, cost and the result of its last test run, for the sessions board. It keeps a history of each session's figures, without any text of its log, and a cache it can rebuild, and sends nothing anywhere.

| Log                    | Where                                                                            | What counts                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ---------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Claude Code transcript | `projects/<folder>/<session>.jsonl` in the Claude Code home                      | The last `cost-state` line: Claude Code's own cost, API plus tool time and tokens per model. Without one yet (a session still running), each message's usage once, of the main transcript only, and no cost. A subagent's transcript is not read: the session's `cost-state` covers it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Codex rollout          | `sessions/YYYY/MM/DD/rollout-*.jsonl` and `archived_sessions/` in the Codex home | Token totals of `token_count` events, priced per model at OpenAI's list prices in `src/prices.ts` (dated, marked as estimates; a model without a price, or another provider's, is named in `unpriced`); turn times of `task_complete` events, which include waits for an approval. A fork counts only what it added: the history it copied from its parent, up to its own `thread_settings_applied` line, is skipped, and its tokens start from the totals it took over. A fork recorded before openai/codex f5636bb733 (2026-08-29) has no thread id on that line, so it shows 0 tokens and time: it undercounts instead of counting twice. A subagent's rollout (its parent named in `source` or at the top level of `session_meta`) adds its tokens, cost and time to its root session; the root's tests stay its own. |

- Tests: the last test run with a readable result decides. Runs are found by tokenizing the command with `shell-quote`, heredoc bodies left out: `npm test`, `pnpm --filter x run test`, `pytest`, `go test` and the like; one behind a wrapper (`timeout 600 npm test`, `devcontainer exec ... pnpm test`) is not found. A run's exit code is its result when the run is the command's last step. Piped on (`npm test 2>&1 | tail`) or followed by another command, the summary line in the command's output is (`2 failed`, `2 errors in`, `Errors  1 error`, `11 passed`), a later command's line such as `1 failing` from `gh pr checks` included. A run without a readable result, or one that never ran, leaves the earlier result. Codex records command results only in its paginated history mode, so its sessions in the default mode show none; it records the shell by its path (`/bin/zsh -lc 'npm test'`), and a run the user declined or that did not start (exit code -1) never ran. A PowerShell `-Command` run on Windows is not found.
- Board: `boardOf` cuts the rows to a period of calendar days up to today in the user's time zone (the view's, or the machine's for the CLI) and to a project, names the first day of Claude Code data (`first`: the history's oldest Claude Code session; Claude Code deleted older transcripts before the board read them, so earlier days have no data), and gives the figures the board shows: sessions, agent time, tokens, cost and the sessions without one, days worked and the longest run of them, and the share of tested sessions whose last run passed.
- History: `sessions-history.json` in CedarLoom's state folder (`CEDARLOOM_STATE_DIR`, else `XDG_STATE_HOME/cedarloom`, else `~/.local/state/cedarloom`; the CLI's `--state`), readable by this user only (mode 0600 on macOS and Linux) and never sent anywhere. One row per session: the agent and the session id, the project folder, the start time, agent time, tokens, cost and the test result. It never holds a title, prompt, command, output, model name or any other text of a log. Each read of the board (the Sessions view or `cedarloom board`) records the sessions whose logs it finds and keeps the rows of sessions whose logs are gone. The board therefore still counts them after Claude Code deletes transcripts older than its `cleanupPeriodDays` (30 days by default, [data retention](https://code.claude.com/docs/en/data-usage#data-retention)), or after a session is deleted in its agent tool. Only a read records: a log deleted before the board next reads it is missing from the history. A row whose log is gone has no title, and its end is its start. Delete the history with Delete history in the Sessions view, with `cedarloom board --delete-history --yes`, or by deleting the file. The rows of sessions whose logs are gone are then lost; the rows of sessions whose logs still exist are recorded again at the next read. A history that is not JSON is moved aside to `sessions-history.json.bad` (replacing an older one; CedarLoom never deletes it), the board says so once, and a new history starts; a row this version cannot read is dropped; a file that cannot be read or moved aside, or of another version, is left as it is and not shown.
- Project: the main worktree of the repository the session's folder is in, read from the `.git` entries as git reads them (a `.git` file only as a regular file of at most 1 MiB), without running git, else the folder (also when its `.git` is one git refuses, where git stops looking too).
- Cache: one JSON file of summaries (no message text but the session title) for the logs that still exist, re-read when a log's size or modification time changes. Deleting it loses only the project of a session whose worktree is gone since: that one then counts under its folder.
- Formats: both tools' log formats are undocumented. The Claude Code fixtures are two recorded sessions (Claude Code 2.1.316), scrubbed; the Codex fixtures are built from the rollout types in openai/codex at commit 8703d32b and are unverified against a recorded rollout. Codex's `input_tokens` include the cached and the written tokens (its test `parses_cache_write_token_usage`). Not read yet: compressed rollouts (`rollout-*.jsonl.zst`, which Codex writes only with its `local_thread_store_compression` feature on), and the service tier, so a Fast-tier turn is priced at Standard rates.
- Agent time is API plus tool time summed, so parallel subagents and tools can make it longer than the session.
