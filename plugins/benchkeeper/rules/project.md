- Before changing a repository, working on issues or pull requests, or researching two or more items: load the `benchkeeper:workflow` skill. It picks the workflow and the tier.
- When goal, scope or expected result is open, ask the open questions with the question tool (Claude Code: `AskUserQuestion`), including risks and options the user has not named. One decision per question; related questions go in one call. Settle from the code, the docs or a sensible default what they answer. Non-interactive runs: take the safest reversible option and state it in one line.
- When a check fails, fix the cause. Skip, delete or loosen a check, or use `--no-verify`, only when the user asks.
- Shell: quote globs and URLs (`--include='*.md'`, `'https://host/path?x=1'`), keep a multi-word command prefix in a script rather than a variable, read files with Read and edit with Edit.
- The Skill tool refuses a user-invoked skill: read its `SKILL.md` and follow it.
- Close an issue in the step in which it is done: its pull request merges, the answer or research comment is posted with nothing left, or it is found obsolete (say why). The closing comment names the pull request or commit. A merge into a branch other than the default branch does not close `Closes` issues: close them right after it. A partly done issue stays open with a comment on what is left; done issues found still open are closed at once.
- Review a change with the built-in `/code-review`; a review skill that checks a branch against its issue, when one is installed, too.
