BenchKeeper

Global agent setup for Claude Code and Codex: rules, two skills, rebuild steps.

BenchKeeper keeps the agent's workbench in order: the rules, skills and tools Claude Code and Codex work with, installed at pinned versions and checked on every /global-setup run. The bench is shared by every project; each repository gets its own container and spec setup on top.

Setup steps See the SDLC

What it is

A Git repository with one rules file and two skills. The skills install, check and clean the tools each agent uses. Claude Code and Codex are independently optional: setup detects installed agents and configures only the ones you select.

rules/global.md

Global, both agents

How agents work in every repository: ask instead of assuming, sources for claims, issue to pull request flow, SDLC phases, safety, devcontainer use. Symlinked for Claude Code, copied to ~/.codex/AGENTS.md for Codex.

/global-setup

Once per machine

Checks 11 parts plus one optional part, installs what is missing after confirmation, proposes cleanup. Every install command pins an exact version; the skill proposes version bumps before installing.

/project-setup

Once per repository

Devcontainer, AGENTS.md, stack skills, language servers, spec tool (OpenSpec, Spec Kit or none), codegraph, dead config. On an existing setup it proposes only the differences.

One loop for every change

The global rules route each change through the same ten steps. agent-skills supplies the skill for each phase, Ponytail keeps the implementation small, and OpenSpec or Spec Kit holds the spec files when the repository uses one.

  1. UnderstandRead AGENTS.md, the issue and the code the change touches before any edit.
  2. TrackNo issue yet: the agent presents title, goal, acceptance criteria and tasks, and creates the issue after approval.
  3. Branch<type>/<issue>-<slug>, never work on the default branch without being told to.
  4. Specifyspec-driven-development, written as an OpenSpec change or a Spec Kit feature spec when the repository has one.
  5. Planplanning-and-task-breakdown into small tasks with acceptance criteria.
  6. Buildincremental-implementation, tests first where a test suite exists, Ponytail full for the smallest complete change.
  7. VerifyBuild, types, lint and tests inside the devcontainer; UI changes in a browser through Playwright MCP.
  8. ReviewCorrectness review of the commits before git push; findings stop the push until you decide.
  9. ShipDraft pull request with Closes #n, wait for checks, mark ready. Merge only on your instruction.
  10. MaintainAbout every 10 merged changes: ponytail-audit, ponytail-debt, dependency audit, docs drift, repository hygiene.

Where things run

The agent and its configuration stay on the host. Project commands run in the repository's standard devcontainer, which mounts only the project.

Host one per machine

  • Claude Code / Codex, sign-in and permissions
  • Global rules and skills: agent-skills, Ponytail, global-setup, project-setup
  • RTK, Context7 MCP, OpenSpec and Spec Kit CLIs
  • Git and gh: branches, commits, pull requests
  • Dev Containers CLI and Docker
devcontainer exec

Devcontainer one per repository

  • Project toolchain at pinned versions
  • Installs, builds, lint, tests
  • codegraph index and MCP server
  • Playwright browser, language servers
  • Non-root user, project mount only, no host home, no engine socket, no credential forwarding

What each part gives you

Each component is a separate upstream project. BenchKeeper pins it, configures it, and connects it to the rules.

agent-skills

Global, both agents

Workflow skills for the lifecycle phases Define, Plan, Build, Verify, Review and Ship: spec, planning, TDD, debugging, code review, security, shipping.

Ponytail full

Global, both agents

The smallest change that solves the whole task: reuse before new code, no unrequested options or abstractions, a test for non-trivial logic, shortcut: comments for known limits.

OpenSpec or Spec Kit

CLI global, chosen per repository

Spec files committed with the code. OpenSpec: one change folder per change, merged into living specs on archive. Spec Kit: one folder per feature plus a constitution.

codegraph

Per repository, in the container

A local graph of symbols, callers and impact, queried over MCP instead of file-by-file search. Offered at about 50 or more source files.

RTK

Global, both agents

Compresses shell command output (tests, builds, linters, git) before the agent reads it.

Context7 MCP

Global, both agents

Current library and framework documentation on request, so API usage comes from docs instead of training data.

Playwright MCP

Per repository, browser in the container

The agent opens the running application, clicks through it and checks UI changes in a real browser.

Dev Containers

CLI on host, config per repository

One container configuration shared by the CLI, VS Code and Orca terminals. Project commands get the same toolchain on every machine.

Stack skills and LSP

Per repository

find-skills picks at most two vetted skills per technology. Language servers give diagnostics after the connection to the container is verified.

How it raises quality

Each item is a rule the agents load in every session. Source: rules/global.md.

  • Ask, do not assume. Ambiguous requests stop for precise questions instead of a guess.
  • Spec before code. Non-trivial changes get a written spec and a task list.
  • Tests first where the repository has a test suite; non-trivial logic leaves a test.
  • Checks are never weakened. No skipped tests, loosened assertions, disabled lint rules or --no-verify unless you ask.
  • Review before push. A correctness review runs on the commits; findings wait for your decision.
  • Sources and confidence. External claims carry an official URL; uncertain topics state a confidence level.
  • Reproducible tools. Exact versions for every install and container image.
  • Scheduled cleanup. The Maintain pass finds dead code, stale shortcuts, vulnerable dependencies and docs drift.

Cost the setup avoids

  • Optional parts are skipped where they do not apply: no spec tool for config and docs repositories, no codegraph below about 50 source files.
  • Telemetry is off for Codex, RTK, OpenSpec and codegraph; Claude Code error reporting and feedback surveys are off.
  • A new machine is rebuilt from one repository with /global-setup; a fresh clone restores its skills with /project-setup.

What it is not

  • Not an agent. It configures Claude Code and Codex; it does not replace them and does not install their CLIs.
  • Not a sandbox for the agent. The devcontainer scopes project commands and mounts; the agent stays a host process under its client permissions.
  • Not a hosted service. BenchKeeper is files in a Git repository; it runs no server and has no account.
  • Not a build system or framework. Docs and config only; your project keeps its own toolchain.
  • Not auto-updating. Versions change only when /global-setup proposes a bump and you accept it.
  • Not autonomous on your repository. Issues are created after approval; merges, pushes to the default branch and destructive actions need your instruction.
